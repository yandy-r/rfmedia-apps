## Summary

The recency design is well integrated and the full validation suite passes, but two adapter-boundary
validation gaps can turn accepted wire data into unsafe policy behavior. The ROADMAP update remains
intentionally deferred until the real PR number exists, as required by the delivery plan.

## Findings

### CRITICAL

- None.

### HIGH

- **[F001]** `packages/rfmedia-cli/src/lib/adapters/plex/types.ts:455` — The wire guard accepts positive safe-integer epoch seconds beyond JavaScript's ISO-renderable Date range, while the stale rule unconditionally calls `toISOString()`. One guard-approved value can therefore degrade the whole rule with a `RangeError`. [correctness, security, quality]
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Bound `lastViewedAt` to the maximum ISO-renderable epoch second and add accepted-boundary plus out-of-range guard/query coverage.
- **[F002]** `packages/rfmedia-cli/src/lib/adapters/plex/types.ts:498` — `lastViewedAt` is accepted independently of `viewCount`, so an old timestamp with missing or zero `viewCount` maps to `playCount: 0` and can satisfy both the default lifetime ceiling and recency gate once another artist makes the library total nonzero. [correctness]
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Reject a present `lastViewedAt` unless the same wire row carries a positive finite `viewCount`, and add guard/query/rule regression coverage for missing and zero counts.

### MEDIUM

- **[F003]** `packages/rfmedia-cli/README.md:5457` — The example says its thresholds admit a cohort but omits the rule's `enabled` state; the root example has the same ambiguity even though the rule defaults disabled. [quality]
  - **Status**: Fixed
  - **Category**: Completeness
  - **Suggested fix**: Make activation explicit in both examples: enable the executable README example and keep the root example safely disabled with a clear opt-in comment.

### LOW

- **[F004]** `packages/rfmedia-cli/src/types/media-server.ts:65` — The provider-neutral domain contract describes `lastViewedAt` as Plex- and credential-specific, leaking adapter provenance into the generic media-server boundary. [quality]
  - **Status**: Fixed
  - **Category**: Pattern Compliance
  - **Suggested fix**: Describe the field as whole epoch seconds for the latest view reported by the media server; retain Plex/account provenance in the private wire type and policy docs.
