## Findings

### CRITICAL

No findings.

### HIGH

- **[F001]** `packages/rfapps-cli/src/actions/deploy.ts:500` — A runtime-evidence failure discards the already-resolved canonical project, effective dependency closure, successful evidence lanes, and completed checks; the fallback reports project `unknown` and the pre-closure selection instead. [correctness, quality]
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Preserve safe scope and per-lane results through evidence collection, construct the inconclusive result from completed and failed checks, extend V3 to assert the full scope/check/message contract, and align the documented example.

- **[F002]** `packages/rfapps-cli/src/actions/deploy.ts:471` — A relative dotenvx or 1Password provider path is validated from the invocation directory but later executed from the Compose project directory, allowing a different same-named secrets file to be loaded and pinned. [security]
  - **Status**: Fixed
  - **Category**: Security
  - **Suggested fix**: Canonicalize the provider file relative to the original invocation directory before changing cwd, pass only the absolute path, and add a regression test with distinct same-named files.

- **[F003]** `packages/rfapps-cli/src/lib/conflict-validation.ts:535` — Per-input size limits do not bound aggregate claims, comparisons, findings, or the overall evidence stage, so large valid models can trigger unbounded pairwise work or many sequential command timeouts instead of a stable inconclusive result. [security]
  - **Status**: Fixed
  - **Category**: Performance
  - **Suggested fix**: Enforce global claim, comparison-work, finding, and evidence-stage budgets with a deterministic inconclusive failure and regression tests at each boundary.

- **[F004]** `packages/rfapps-cli/src/lib/docker.ts:2465` — Canonical Compose service keys permit a leading dash; after deploy-all scope expansion, a service such as `--help` becomes a Docker Compose operand without an option terminator and can change the command shape. [security]
  - **Status**: Fixed
  - **Category**: Security
  - **Suggested fix**: Validate every service and dependency reference that can become a CLI operand with the existing non-leading-dash operand grammar, and add `--help` plus value-taking-option regressions.

### MEDIUM

- **[F005]** `docs/features/dry-run-mode.md:267` — The guide says dry-run does not decrypt secrets, but `--dry-run --validate-first` resolves the same secret-injected effective environment as deploy.
  - **Status**: Fixed
  - **Category**: Completeness
  - **Suggested fix**: Distinguish ordinary dry-run from validate-first dry-run and state that values are resolved but never logged or persisted.

- **[F006]** `packages/rfapps-cli/src/actions/deploy.spec.ts:476` — Action tests do not cover the new text/table projections for passed, blocked, and inconclusive validation results, leaving duplicate or missing human output undetected.
  - **Status**: Fixed
  - **Category**: Completeness
  - **Suggested fix**: Add text and table cases that assert one projection, no prompt or mutation on non-pass, and no machine serialization in text mode.

- **[F007]** `packages/rfapps-cli/src/actions/deploy.ts:159` — Validation coordination, projection, parsing, and rendering expanded `deploy.ts` to 1,512 lines, while the evaluator and Docker adapter also exceed the checklist's 800-line maintainability threshold. [correctness, quality]
  - **Status**: Fixed
  - **Category**: Maintainability
  - **Suggested fix**: Extract a cohesive deploy-validation coordinator and focused resource/evidence modules behind the existing public facades.

- **[F008]** `packages/rfapps-cli/src/actions/deploy.ts:875` — Passing human-readable validation evidence is emitted only after confirmation, so users authorize deploy without seeing the preflight decision and cancellation suppresses it.
  - **Status**: Fixed
  - **Category**: Completeness
  - **Suggested fix**: Emit the passing human projection before confirmation and keep a successful binding recheck silent.

- **[F009]** `packages/rfapps-cli/src/lib/conflict-validation.ts:46` — Display sanitization removes C0/C1 characters but preserves Unicode bidirectional formatting controls that can visually reorder operator-controlled identifiers in terminals and logs.
  - **Status**: Fixed
  - **Category**: Security
  - **Suggested fix**: Replace bidi override/isolate controls in both structured and human output and add regression tests.

No findings.
