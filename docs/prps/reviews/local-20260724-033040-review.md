The artist-delete implementation follows the reviewed plan and passed the repository's

## Findings

### CRITICAL

- **[F001]** `packages/rfmedia-cli/src/lib/lidarr/plan-engine.ts:2346` — Persisting a terminal `uncertain` artist-delete result replaces the entry's durable `possibly-dispatched` record. A resumed run can therefore lose attribution for an absent artist or resend the non-idempotent delete when the artist remains present.
  - **Status**: Fixed
  - **Category**: Security
  - **Suggested fix**: Preserve and validate possible-dispatch evidence independently or carry the matching idempotency key on uncertain deletion history. Add two-invocation tests for both present and absent resume states and prove that neither blindly resends the delete.

### HIGH

- **[F005]** `packages/rfmedia-cli/src/actions/lidarr/apply-artist-entry-execution.ts:293` — A definitive non-retryable delete rejection can be persisted as ambiguous dispatch because the artist-delete inconclusive branch runs before the non-retryable error branch. This retains possible-dispatch evidence and permanently blocks recovery after credentials are corrected.
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Retain uncertain possible-dispatch state only when the request may genuinely have reached Lidarr. Persist definitive HTTP rejection as failed, clear possible-dispatch evidence, and add two-invocation rejected-delete recovery tests.

### MEDIUM

- **[F002]** `packages/rfmedia-cli/src/lib/lidarr/plan-operation-definitions.ts:134` — The `deferability` discriminant does not constrain the registry contract, so the non-deferable delete operation still exposes an empty deferred-operation name and throwing executor stub.
  - **Status**: Fixed
  - **Category**: Maintainability
  - **Suggested fix**: Make operation definitions a discriminated union where only deferable operations expose deferred execution fields, narrow at queue and replay call sites, and remove the artist-delete deferred stubs.

- **[F003]** `packages/rfmedia-cli/src/lib/lidarr/errors.ts:276` — Mapping every HTTP 404 in the shared classifier to `LidarrNotFoundError` changes behavior beyond the targeted artist-read boundary required by issue #200.
  - **Status**: Fixed
  - **Category**: Pattern Compliance
  - **Suggested fix**: Preserve the shared classifier's existing behavior and specialize the targeted `getArtist` boundary, with tests proving artist-read 404 is typed absence while non-targeted 404 behavior is unchanged.

- **[F004]** `packages/rfmedia-cli/src/commands/lidarr-mutation-presenter.ts:550` — The confirmation prompt labels every artist tag mutation as destructive tag replacement, including additive `add` and `remove` plans.
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Gate the destructive wording with `requiresTagReplacementAuthorization(reviewedPlan)` and add focused prompt coverage for additive versus replacement modes.

- **[F006]** `packages/rfmedia-cli/src/actions/lidarr/apply.ts:970` — Resume dry-run reports a present artist with possible-dispatch evidence as `would-apply`, while real execution blocks the same entry as `possible-dispatch-pending`.
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Carry the possible-dispatch-present state into dry-run output and report the same uncertain blocked recovery outcome without writing history or claims. Add a resume dry-run regression test.

- **[F007]** `packages/rfmedia-cli/src/lib/lidarr/plan-operation-definitions.ts:152` — The deferable definition base receives a union kind, permitting mismatched `kind` and `operation` pairs and weakening the discriminated-union contract.
  - **Status**: Fixed
  - **Category**: Maintainability
  - **Suggested fix**: Define deferable definitions as a distributed union keyed by each operation kind so `kind` and `operation` remain correlated.

- **[F009]** `packages/rfmedia-cli/src/actions/lidarr/apply-artist-entry-execution.ts:288` — A definitively rejected delete can still be recorded as succeeded when a concurrent external deletion makes reconciliation observe the artist as absent.
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Handle definitive non-retryable dispatch errors before switching on reconciliation state, persist failed, and clear possible-dispatch evidence regardless of the subsequently observed state. Add a regression test where delete returns 401 and verification returns 404.

### LOW

- **[F008]** `packages/rfmedia-cli/src/lib/lidarr/client.ts:412` — Targeted artist 404 conversion depends on comparing the complete error message, so wording changes can silently break typed absence.
  - **Status**: Fixed
  - **Category**: Maintainability
  - **Suggested fix**: Preserve HTTP status in stable typed error metadata or use a dedicated internal error code/subclass, then discriminate on that stable field.
