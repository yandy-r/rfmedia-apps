### HIGH

- **[F001]** `packages/rfmedia-cli/src/lib/completed-tracker.ts:327` — Failed-sidecar migration discards each original `# Error:` diagnostic, persists a generic message, and still returns cleanup proof, so deleting the sidecar loses recoverable failure state.
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Parse source/error pairs, persist the exact diagnostics, and require exact failed-row equivalence before returning deletion proof; regress preservation and idempotent equivalence.

- **[F002]** `packages/rfmedia-cli/src/actions/migrate-tracking.ts:103` — Cleanup identity is captured only after import proof and deletion later uses the requested pathname after separate checks, allowing a replaced file or parent-symlink swap to be treated as the proven import and mutated.
  - **Status**: Fixed
  - **Category**: Security
  - **Suggested fix**: Capture canonical root and leaf identity before import, bind that identity to accepted importer proof, revalidate after import and immediately before mutation, and delete through the verified canonical or atomic boundary; add replacement-before-capture and parent-symlink-race regressions.

- **[F003]** `packages/rfmedia-cli/src/actions/sync.ts:244` — Sync replacement and persistence are not atomic: hardlink updates remove the old artifact before replacement, ranged inventory commits after the first suffix, and post-materialization failures strand untracked output or miss inventory after a first-suffix collision.
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Stage all required destinations, validate and hash them, atomically publish authorized targets, then append one inventory record and count success; roll back uncommitted new output while preserving old updated artifacts, with focused regressions for each failure boundary.

- **[F004]** `packages/rfmedia-cli/src/actions/sync.ts:809` — Database ownership begins before the protecting `try/finally`, so setup failures during operation creation, inventory initialization, signal-handler loading, or cleanup registration leak the open connection.
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Establish the resource-owning `try/finally` immediately after database acquisition and add setup-failure tests proving exactly one close without double cleanup.

- **[F007]** `packages/rfmedia-cli/src/actions/migrate-tracking.ts:253` — One tracking importer rejection aborts later independent operation groups instead of returning stable per-path migration errors.
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Contain each group failure, retain its sidecars, record path/code/message, and continue importing later groups.

### MEDIUM

- **[F005]** `packages/rfmedia-cli/src/actions/sync.ts:1043` — Final database counts subtract per-file failures from scanned-source totals, which can produce negative completed counts and incorrect source-level status.
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Track source-level success and failure explicitly and update operation counts/status from those outcomes; regress multiple file failures within one source.

- **[F006]** `packages/rfmedia-cli/src/lib/history.ts:820` — Legacy history timestamp validation accepts any `Date.parse`-compatible value rather than the writer's ISO-8601 shape, allowing malformed but parseable sessions to become cleanup-eligible.
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Require the writer's ISO-8601 timestamp syntax in addition to parse validity and add malformed-but-parseable timestamp coverage.

None.
