# Local Review — Issue #125 Metadata Drift Reconciliation

**Reviewed**: 2026-07-29T00:36:13Z
**Mode**: Local
**Branch**: feat/125-metadata-reconciliation
**Decision**: BLOCK

## Summary

The three-lens review found a well-specified fail-closed reconciliation workflow with focused
contract coverage, but identified one critical database path-swap risk, five high-severity
correctness and capability gaps, and three medium performance/completion gaps. The branch must
not be opened for merge until every finding is fixed and independently re-reviewed.

## Findings

### CRITICAL

- **[F001]** `packages/rfmedia-cli/src/actions/reconcile.ts:639` — Execution reopens the reviewed database path through the generic initializer, which can create, migrate, or follow a swapped database before the row guard runs.
  - **Status**: Fixed
  - **Category**: Security
  - **Suggested fix**: Add a reconciliation-specific writable opener that requires an existing non-symlink regular file, uses `fileMustExist: true`, performs no initialization or migration, and verifies the same device/inode snapshot before and after opening. Keep revalidation reads immutable and acquire the writable connection only when an actual database target is ready.

### HIGH

- **[F002]** `packages/rfmedia-cli/src/actions/reconcile.ts:231` — A failed per-file metadata read remains embedded in the report while scan and preview still return success and exit zero.
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Propagate per-file acquisition failures out of acquisition and return a non-success `read-failed` result; add scan and preview tests asserting nonzero exit semantics.

- **[F003]** `packages/rfmedia-cli/src/actions/reconcile.ts:640` — Execution does not freshly revalidate the selected database row and exact server track immediately before each record's first mutation, so stale authority or track identity can overwrite newer state before post-scan detects it.
  - **Status**: Fixed
  - **Category**: Security
  - **Suggested fix**: Immediately before each record's first write, freshly query and compare the selected database row and perform an uncached exact-path server lookup proving unique identity and rating. Return `stale-evidence` before any write on a mismatch or ambiguity, including changes between records.

- **[F004]** `packages/rfmedia-cli/src/actions/reconcile.ts:728` — File verification compares the reread normalized rating to the unencoded intended float even though MP3 and FLAC writers quantize values and encode zero as unrated, causing false failures after a real mutation.
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Canonicalize intended ratings through the selected file format and scale before planning and verification, distinguish unrepresentable zero, and mark a path touched as soon as the writer succeeds so post-scan verifies every attempted mutation; add MP3 and FLAC edge regressions.

- **[F005]** `packages/rfmedia-cli/src/lib/reconciliation.ts:485` — Planning infers server writability from unique identity without checking the adapter's rating-write capability, allowing a read-only adapter to produce an executable plan.
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Carry the adapter rating-write capability into the engine report and require it when planning a server target; prove a read-only adapter produces an `unsupported-target` blocker without opening mutation dependencies.

- **[F006]** `packages/rfmedia-cli/src/lib/reconciliation.ts:589` — `server-wins` can suppress both losing writes using native-step equivalence even when the scan still classifies the three-plane values as conflicting, allowing apply to report convergence while drift remains.
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Use one equivalence rule for planning and postcondition convergence; when the losing file and database values conflict, plan their writable targets to the canonical server value even if each is independently within one native server step.

- **[F007]** `packages/rfmedia-cli/src/actions/reconcile.ts:210` — Documented `--workers` and `--no-progress` controls are accepted but unused; acquisition is serial, materializes all paths, and emits no progress behavior.
  - **Status**: Fixed
  - **Category**: Completeness
  - **Suggested fix**: Honor `options.workers` with a bounded, cancellation-aware metadata pool that restores deterministic order, and implement stderr progress gated by `options.progress` with machine-output suppression coverage.

### MEDIUM

- **[F008]** `packages/rfmedia-cli/src/actions/reconcile.ts:659` — Per-record execution repeatedly linearly searches records and outcomes, making a supported 10,000-row apply quadratic.
  - **Status**: Fixed
  - **Category**: Performance
  - **Suggested fix**: Build maps for records and stable outcome keys before the loop and update outcomes in constant time, reserving full-array passes for final normalization.

- **[F009]** `packages/rfmedia-cli/src/lib/shell-completions/bash.ts:19` — Bash, Zsh, and Fish omit the registered top-level `plugin` command while the updated guide claims all current commands are completed.
  - **Status**: Fixed
  - **Category**: Pattern Compliance
  - **Suggested fix**: Add `plugin` and its `list`, `info`, and `dir` subtree to all three templates, add a cross-shell parity assertion, and include it in the documented command table.

### LOW

None.
