## Summary

Three independent review passes covered correctness, security, and implementation quality. The
review found one apply-admission safety gap, one CSV export hardening gap, one Fish completion
parity gap, two small consistency issues, and three maintainability findings in the newly expanded
apply, plan-engine, and command modules. Two fix re-reviews found and resolved four additional
trust-boundary and maintainability issues. A post-rebase integration review found and resolved one
album-monitoring deferred-history regression; the final independent re-review was clean. No
critical findings were reported.

## Findings

### CRITICAL

None.

### HIGH

- **[F001]** `packages/rfmedia-cli/src/actions/lidarr/apply.ts:608` — Apply preflight resolves only operation resources, so resources sealed exclusively in `plan.selection` are not revalidated before writes.
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Preflight the deduplicated union of operation and selection references, load every required catalog, and test selector-only profile and tag deletion and rename.

- **[F009]** `packages/rfmedia-cli/src/actions/lidarr/apply.ts:1362` — Destructive tag replacement authorization is enforced only by Commander, so direct action callers can execute `set` and `clear` plans with generic approval.
  - **Status**: Fixed
  - **Category**: Security
  - **Suggested fix**: Require explicit `allowTagReplacement` authorization in the action for non-dry-run replacement plans, thread it from the CLI, and add zero-write action tests.

- **[F013]** `packages/rfmedia-cli/src/actions/lidarr/apply-target-execution.ts:473` — Album target-read failures attempt to build v2-only failure evidence after queuing deferred work, throwing before durable history is persisted.
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Preserve the v1 album result contract while persisting the deferred outcome and add regression coverage for both the queued intent and durable history.

### MEDIUM

- **[F002]** `packages/rfmedia-cli/src/lib/formatters/index.ts:24` — CSV formula neutralization omits tab, carriage-return, and line-feed prefixes recognized as spreadsheet injection vectors.
  - **Status**: Fixed
  - **Category**: Security
  - **Suggested fix**: Neutralize all three control-character prefixes for CSV only and add regression tests without changing JSON or YAML values.

- **[F003]** `packages/rfmedia-cli/src/lib/shell-completions/fish.ts:1242` — New value-taking Lidarr options omit Fish's required-argument marker even though Bash, Zsh, and Commander require values.
  - **Status**: Fixed
  - **Category**: Pattern Compliance
  - **Suggested fix**: Add `-r` to every value-taking Lidarr option and extend parity tests to verify argument arity, retaining candidate completions where present.

- **[F004]** `packages/rfmedia-cli/src/actions/lidarr/apply.ts:741` — The apply module now combines preflight, deferred replay, reconciliation, lifecycle, and result assembly in several oversized functions.
  - **Status**: Fixed
  - **Category**: Maintainability
  - **Suggested fix**: Extract focused apply helpers for the newly added resource preflight and mutation/reconciliation concerns while preserving the public action contract.

- **[F005]** `packages/rfmedia-cli/src/lib/lidarr/plan-engine.ts:592` — The expanded plan engine combines immutable v1 compatibility, v2 schemas, operation definitions, storage, history, and claim ownership.
  - **Status**: Fixed
  - **Category**: Maintainability
  - **Suggested fix**: Extract the newly added v2 operation-definition concerns behind the existing public barrel while preserving canonical output and v1 golden tests.

- **[F006]** `packages/rfmedia-cli/src/commands/lidarr.ts:909` — Mutation-plan rendering, apply approval, failure handling, and Commander registration are tightly coupled in the enlarged Lidarr command module.
  - **Status**: Fixed
  - **Category**: Maintainability
  - **Suggested fix**: Extract mutation rendering and approval workflow helpers, leaving Commander registration to typed delegation.

- **[F010]** `packages/rfmedia-cli/src/commands/lidarr-mutation-presenter.ts:241` — JSON quoting does not make the displayed recovery command shell-safe for paths containing substitutions, backticks, quotes, or glob characters.
  - **Status**: Fixed
  - **Category**: Security
  - **Suggested fix**: Use POSIX single-quote shell escaping and test substitutions, backticks, quotes, spaces, and glob characters.

- **[F011]** `packages/rfmedia-cli/scripts/check-direct-plex-imports.mjs:310` — The mutation-ownership audit detects property access but can be bypassed with string-literal element access or destructured/aliased client methods.
  - **Status**: Fixed
  - **Category**: Security
  - **Suggested fix**: Detect element-access calls and destructured or aliased mutation bindings, with negative architecture fixtures for each syntax.

- **[F012]** `packages/rfmedia-cli/src/actions/lidarr/apply.ts:685` — Resource preflight was extracted, but deferred replay and per-target admission/reconciliation remain oversized state machines in the action coordinator.
  - **Status**: Fixed
  - **Category**: Maintainability
  - **Suggested fix**: Extract deferred replay and per-target mutation/reconciliation into focused modules while retaining the public action as lifecycle coordinator.
