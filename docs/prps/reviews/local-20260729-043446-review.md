# Local Re-review 9 — Issue #125 Metadata Drift Reconciliation

**Decision**: BLOCK

## Summary

The ninth review found two remaining high-severity authority races and one medium-severity Bash
completion routing defect. The database lease needed to revalidate its full generation after
acquiring the write lock, the MP3 writer needed to reject an untrusted source inode, and Bash
completion needed to consume value-taking reconciliation options while detecting the command path.

## Findings

### CRITICAL

None.

### HIGH

- **[Z001]** `packages/rfmedia-cli/src/lib/db.ts:638` — The authority lease checked the reviewed
  database generation before `BEGIN IMMEDIATE`, leaving a competing-commit interval before lock
  acquisition.
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Revalidate device, inode, size, mtime, and ctime after `BEGIN IMMEDIATE` and
    before schema or row access; roll back on mismatch.

- **[Z002]** `packages/rfmedia-cli/src/lib/tag-writer.ts:670` — The MP3 publisher trusted the
  directory chain but did not require the source inode to have trusted ownership and no group,
  world, or ACL-effective write access.
  - **Status**: Fixed
  - **Category**: Security
  - **Suggested fix**: Require effective-user/root ownership, reject mode `0o022`, revalidate
    immediately before publication, and prove a concurrent foreign write cannot be discarded.

### MEDIUM

- **[Z003]** `packages/rfmedia-cli/src/lib/shell-completions/bash.ts:217` — Bash command detection
  treated reconciliation option values as command tokens and routed all non-option values to
  directory completion.
  - **Status**: Fixed
  - **Category**: Completeness
  - **Suggested fix**: Consume value-taking reconciliation options and add value-specific runtime
    completion coverage.

### LOW

None.
