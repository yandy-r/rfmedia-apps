## Summary

The fourth independent correctness, security, and quality review verified that T001–T006 are fixed.
It found five high-severity residuals in database freshness, server self-mutation handling,
DB-authoritative projection, request cancellation, and hardlink-safe file mutation. Five medium

required before opening the pull request.

## Findings

### CRITICAL

None.

### HIGH

- **[U001]** `packages/rfmedia-cli/src/actions/reconcile.ts:782` — Exact database freshness rereads
  require `O_RDWR`, `BEGIN IMMEDIATE`, and a WAL checkpoint even when no database target is planned,
  so a read-only or locked database can block an otherwise valid file/server repair.
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Use a pinned read-only exact-row snapshot for freshness and open the guarded
    writable transaction only when executing a database target.

- **[U002]** `packages/rfmedia-cli/src/actions/reconcile.ts:1003` — Each record compares against the
  invocation's original server content version, so a successful server mutation can invalidate all
  subsequent records through the command's own version change.
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Use membership/path-specific freshness or advance a trusted baseline after
    each known self-mutation while retaining external-change detection.

- **[U003]** `packages/rfmedia-cli/src/lib/reconciliation.ts:646` — `--db-wins` globally replaces the
  selected database value with a file-format quantized value and may then write that projection
  back into the authoritative database.
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Preserve the database value and compute target-specific projections; compare
    file values with representation-aware equivalence.

- **[U004]** `packages/rfmedia-cli/src/actions/reconcile.ts:357` — Full-library `query.tracks()`
  acquisition cannot abort an in-flight request because `MediaQueryOptions` has no signal.
  - **Status**: Fixed
  - **Category**: Completeness
  - **Suggested fix**: Add an optional signal to the provider-neutral query options, forward it to
    the Plex transport without including it in cache identity, and cover an in-flight page abort.

- **[U005]** `packages/rfmedia-cli/src/actions/reconcile.ts:184` — A multiply linked MP3 inside the
  source root passes fingerprint checks, then the pathname-based writer truncates the shared inode
  and mutates aliases outside the reviewed root.
  - **Status**: Fixed
  - **Category**: Security
  - **Suggested fix**: Reject multiply linked files before any file mutation, or atomically replace
    only the reviewed directory entry through a descriptor-anchored boundary; cover an in-root
    hardlink to an out-of-root file.

### MEDIUM

- **[U006]** `packages/rfmedia-cli/src/commands/reconcile.ts:393` — SIGTERM machine output reports
  exit code 130 while the shared signal owner correctly preserves process exit status 143.
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Propagate the owning signal's exit code into the result schema and cover both
    SIGINT and SIGTERM.

- **[U007]** `packages/rfmedia-cli/docs/features/metadata-reconciliation.md:278` — The public
  `read-failed` finding/schema branch contradicts the implemented acquisition-error/no-result
  contract.
  - **Status**: Fixed
  - **Category**: Completeness
  - **Suggested fix**: Remove the unreachable public branch or explicitly reserve it for an internal
    engine distinction, and make the user-facing contract singular.

- **[U008]** `packages/rfmedia-cli/docs/features/media-server-adapter.md:25` — The canonical adapter
  guide omits mandatory `libraryContentVersion()` and `trackById()` freshness methods and their
  uncached/cancellation semantics.
  - **Status**: Fixed
  - **Category**: Documentation
  - **Suggested fix**: Document both methods, required version-change conditions, cache bypass, and
    cancellation behavior.

- **[U009]** `packages/rfmedia-cli/src/actions/reconcile.ts:370` — Count limits do not bound
  aggregate server snapshot bytes, projected metadata/tag sizes, or synchronous whole-file MP3
  rewrite size.
  - **Status**: Fixed
  - **Category**: Performance
  - **Suggested fix**: Bound aggregate acquisition bytes and projected field sizes, and enforce a
    safe MP3 file-size ceiling before execution; add only boundary regressions.

- **[U010]** `packages/rfmedia-cli/src/commands/reconcile.ts:299` — Human output interpolates paths
  and labels containing terminal control and bidirectional-control characters.
  - **Status**: Fixed
  - **Category**: Security
  - **Suggested fix**: Apply a shared terminal-safe projection to all human reconciliation fields
    while preserving raw machine serialization.
