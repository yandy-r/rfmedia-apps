## Findings

### CRITICAL

No findings.

### HIGH

- **[F001]** `packages/rfapps-cli/src/lib/deploy-validation.ts:459` — Authority fingerprint failure rejects before the canonical Compose result becomes resolved scope, causing `project: unknown`, a pre-closure selection, and the wrong Compose-unavailable classification.
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Resolve/project canonical Compose first, settle authority and runtime lanes independently, retain completed checks and scope, and add an authority-failure regression with `DOCKER_AUTHORITY_UNAVAILABLE`.

- **[F002]** `packages/rfapps-cli/src/lib/deploy-validation.ts:488` — An unavailable volume-evidence lane becomes an empty inventory, allowing the evaluator to fabricate `EXTERNAL_VOLUME_MISSING`.
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Carry lane availability into evaluation so unavailable volume evidence cannot support absence/runtime-definition conflicts while desired-only checks remain available; add an external-volume regression.

- **[F003]** `packages/rfapps-cli/src/lib/deploy-validation.ts:175` — An omitted Compose `host_ip` becomes only `0.0.0.0`, so a desired wildcard publish can miss a conflicting runtime IPv6 wildcard claim.
  - **Status**: Fixed
  - **Category**: Security
  - **Suggested fix**: Represent an unspecified bind conservatively as both IPv4 and IPv6 wildcard claims, or fail closed until daemon bind-family behavior is known; add an IPv6 regression.

- **[F004]** `packages/rfapps-cli/src/lib/deploy-validation.ts:472` — The revalidation fingerprint hashes only the narrow projected model, so changes to other resolved Compose inputs can pass revalidation.
  - **Status**: Fixed
  - **Category**: Security
  - **Suggested fix**: Hash the complete parsed `docker compose config` payload before secret-bearing fields are discarded and use that one-way hash for binding/revalidation, without retaining or logging raw values.

- **[F005]** `packages/rfapps-cli/src/lib/docker.ts:2757` — Evidence-stage timeout sends only SIGTERM and still waits indefinitely for `close` if a child ignores it, so the promised stage bound is not hard.
  - **Status**: Fixed
  - **Category**: Security
  - **Suggested fix**: Add bounded terminate-then-SIGKILL escalation and final settlement to the shared subprocess runner, with process-group cleanup where supported and a child-that-ignores-SIGTERM regression.

### MEDIUM

- **[F006]** `packages/rfapps-cli/src/actions/deploy.ts:392` — Table output still appears after confirmation and uses a generic nested-object cell that can truncate required owners, resolutions, and limitations.
  - **Status**: Fixed
  - **Category**: Completeness
  - **Suggested fix**: Add a dedicated table projection or shared human projection, emit passing evidence before confirmation and failures at the no-mutation boundary, avoid duplicate rendering, and test the real table renderer plus ordering.

- **[F007]** `packages/rfapps-cli/src/lib/conflict-validation.ts:49` — Bidi sanitization omits Unicode controls such as ALM, LRM, and RLM.
  - **Status**: Fixed
  - **Category**: Security
  - **Suggested fix**: Replace the complete Unicode `Bidi_Control` set and test representatives outside the current ranges in structured and human output.

- **[F008]** `packages/rfapps-cli/src/lib/docker.ts:1221` — Conflict-specific evidence/parser responsibilities and resource evaluators remain concentrated in oversized multipurpose modules despite the prior boundary finding.
  - **Status**: Fixed
  - **Category**: Maintainability
  - **Suggested fix**: Preserve public facades while extracting a focused Docker conflict-evidence adapter and resource-specific port, volume, and network evaluator modules with shared budget/sanitization utilities.

- **[F009]** `docs/architecture/overview.md:239` — Architecture/data-flow documentation omits the new deploy-validation coordinator and still assigns its responsibilities directly to deploy.
  - **Status**: Fixed
  - **Category**: Pattern Compliance
  - **Suggested fix**: Update overview and data-flow diagrams/module descriptions to show deploy interaction/branching, coordinator ownership, and lower-level dependencies accurately.

No findings.
