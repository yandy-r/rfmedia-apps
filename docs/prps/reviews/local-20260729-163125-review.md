# Local Review — Issue #160 Native Backup

**Reviewed**: 2026-07-29T16:31:25Z
**Mode**: Local
**Author**: local
**Branch**: feat/issue-160-native-backup → origin/master
**Decision**: BLOCK

## Summary

The implementation has strong type, test, manifest, completion, and lifecycle coverage, but the
parallel review found one cleanup data-loss race and six correctness/security blockers. Five
maintainability and documentation findings should also be resolved before publication.

## Findings

### CRITICAL

- **[F001]** `packages/rfapps-cli/src/lib/backup-storage.ts:805` — Incomplete-bundle cleanup recursively deletes a pathname after checking pinned directory handles, so another same-UID process can substitute a different directory before `rm` and have that substitute deleted; reservation failure cleanup has the same race.
  - **Status**: Fixed
  - **Category**: Security
  - **Suggested fix**: Retain and report manifest-less incomplete bundles unless descriptor-relative no-follow deletion is available; remove recursive pathname cleanup and add a substitution-race regression test.

### HIGH

- **[F002]** `packages/rfapps-cli/src/actions/backup.ts:275` — Deferred SIGINT/SIGTERM is re-raised from the action with `setImmediate()`, before the root CLI boundary has necessarily released the root state lock.
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Move signal re-raise ownership to the root CLI boundary and re-raise only after terminal output and root-lock release; add a process-boundary signal test asserting both locks are gone.

- **[F003]** `packages/rfapps-cli/src/actions/backup.ts:598` — Initial Docker-locality, canonical Compose evidence, and authority fingerprint failures occur outside the typed coordinator boundary, so machine output can omit the required terminal `rfapps-backup-result.v1` document.
  - **Status**: Fixed
  - **Category**: Completeness
  - **Suggested fix**: Normalize initial authority/planner-input failures into a typed backup result and emit it through the standard result path; add an integration test for one parseable v1 document on authority failure.

- **[F004]** `packages/rfapps-cli/src/lib/backup-coordinator.ts:407` — Recovery treats a successful exact-ID `docker start` as proof that the container remains active, allowing publication after an immediate crash.
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Re-observe or inspect every captured container after starts, record inactive or missing IDs as recovery failures, and retain the manifest-less bundle; test start-success-then-exited.

- **[F005]** `packages/rfapps-cli/src/lib/backup-planner.ts:263` — Writer overlap relies only on normalized Compose path strings; daemon-side symlink or alternate-mount aliases can leave an aliased writer active while the manifest claims detected writers were stopped.
  - **Status**: Fixed
  - **Category**: Security
  - **Suggested fix**: Return daemon-authoritative canonical identity/alias evidence from bind probes, use it for source deduplication and writer discovery, and fail with `AMBIGUOUS_BIND_PATH` when equivalence or containment cannot be proven.

- **[F006]** `packages/rfapps-cli/src/lib/backup-verify.ts:110` — Verification hashes an artifact before comparing its already-known opened size with the manifest, allowing an untrusted bundle to force unnecessary unbounded I/O and CPU.
  - **Status**: Fixed
  - **Category**: Performance
  - **Suggested fix**: Compare the no-follow opened size first, report `size-mismatch` without streaming, and hash only exact-size artifacts; add a no-stream regression test.

- **[F007]** `packages/rfapps-cli/src/lib/docker-conflict-evidence.ts:430` — Unsupported and missing-source mounts are retained for backup but filtered away from the projection consumed by deploy validation, weakening the existing fail-closed `deploy --validate-first` boundary.
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Make deploy desired-state projection reject non-empty unsupported mounts and bind/volume mounts without a source, or use a backup-specific projection; add both deploy regression tests.

### MEDIUM

- **[F008]** `ROADMAP.md:94` — Issue #160 is marked delivered while its evidence link is still `PR-TBD`, making the live authoritative status premature.
  - **Status**: Fixed
  - **Category**: Maintainability
  - **Suggested fix**: Keep #160 in an in-review state until merge evidence exists, then replace the placeholder with the merged PR and mark it delivered.

- **[F009]** `docs/features/rfapps-backup.md:261` — The restore guide recommends direct privileged extraction into a live destination even though verification provides no authenticity or archive-entry safety validation.
  - **Status**: Fixed
  - **Category**: Security
  - **Suggested fix**: Document private staging extraction with restrictive options, path/link/type validation, approved-content copy, and independently trusted provenance; update the parallel restore guide too.

- **[F010]** `packages/rfapps-cli/src/actions/backup.ts:448` — The 243-line action combines context resolution, preview, approval, signal lifetime, execution, result rewriting, and rendering in one control-flow block.
  - **Status**: Fixed
  - **Category**: Maintainability
  - **Suggested fix**: Extract focused helpers for scope/context resolution, preview construction, approval, and approved execution while keeping `executeBackup` as the orchestration boundary.

- **[F011]** `packages/rfapps-cli/src/lib/backup-planner.ts:43` — `BackupSourceProbeResult` is independently declared in the planner and Docker adapter, allowing safety-critical probe contracts to drift structurally.
  - **Status**: Fixed
  - **Category**: Pattern Compliance
  - **Suggested fix**: Define the probe-result union once in shared backup contracts and import that type in both modules.

- **[F012]** `packages/rfapps-cli/src/lib/backup-storage.ts:280` — The 1,074-line module couples destination trust, publication, cleanup, and read-only verification operations.
  - **Status**: Fixed
  - **Category**: Maintainability
  - **Suggested fix**: Split write/publication operations from read/verification operations with small shared no-follow identity primitives, preserving existing public exports.

### LOW

_None._
