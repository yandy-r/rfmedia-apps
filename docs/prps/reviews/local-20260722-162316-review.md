**Reviewed**: 2026-07-22T16:23:16Z

**Decision**: REQUEST CHANGES

## Summary

The lane scheduler is well tested and preserves the existing Lidarr action contracts, but the
review found two correctness gaps and one bulkhead-sharing issue that must be addressed before the
change is published.

## Findings

### CRITICAL

None.

### HIGH

- **[F001]** `packages/rfmedia-cli/src/commands/lidarr.ts:346` — Successful CSV output fails because `result.execution` exceeds the shared serializer's two-level nesting limit.
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Add a CSV-safe flattened projection and test it with the real CSV formatter.

- **[F002]** `packages/rfmedia-cli/src/lib/lidarr/scheduler.ts:442` — Gated lanes do not require or execute the health/circuit preflight before batch admission.
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Make a lane health preflight an explicit required run option for gated tiers, execute it once before admission, and test gated and local-only behavior.

### MEDIUM

- **[F003]** `packages/rfmedia-cli/src/lib/lidarr/index.ts:132` — Each resolver call creates independent limiters, so concurrent action invocations can exceed configured lane concurrency.
  - **Status**: Fixed
  - **Category**: Pattern Compliance
  - **Suggested fix**: Cache the configured scheduler process-wide with invalidation when the loaded scheduler configuration changes, and test resolver sharing.

### LOW

None.
