### HIGH

- **[F001]** `packages/rfmedia-cli/src/actions/lidarr/profile-presets.ts:720` — A write that throws but is proven converged by read-back receives a `satisfied` outcome, yet the generic non-`succeeded` check marks it as a blocker. This incorrectly prevents later custom format, quality profile, or naming resources from being attempted even though the state machine has established a safe terminal state.
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Treat both `succeeded` and `satisfied` outcomes as safe to continue, and add a multi-resource regression test where the first dispatch throws after mutating live state, read-back proves convergence, and the remaining resources are still dispatched.

- **[F003]** `packages/rfmedia-cli/src/actions/lidarr/profile-presets.ts:605` — Creating a custom format can legitimately add the new format at score zero to an existing quality profile during the required catalog refresh. The later profile stale check still compares against the original under-lock baseline, so it can reject the dependent profile update as drift even though the apply itself caused the projection change.
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Rebase each dependency stage's reviewed baseline after successful custom-format convergence, compare the immediate pre-write profile against that refreshed baseline, and add a regression test with a missing managed format and an existing same-name profile.

- **[F004]** `packages/rfmedia-cli/src/actions/lidarr/profile-presets.ts:756` — If final journal persistence fails, the result changes to `partial` while every resource outcome remains `succeeded`; the result contains no stable run-level error code, phase, retryability, or next action. This contradicts the documented partial-result contract.
  - **Status**: Fixed
  - **Category**: Error Contract
  - **Suggested fix**: Add a run-level safe `LIDARR_PRESET_JOURNAL_WRITE_FAILED` error to the apply result and render it in every output format without changing already verified resource outcomes.

- **[F008]** `packages/rfmedia-cli/src/actions/lidarr/profile-presets.ts:745` — Replacing the entire pending profile baseline with the post-format read-back can also adopt unrelated concurrent profile drift during the format write/read-back window. The later stale check would then permit a profile write that should be rejected.
  - **Status**: Fixed
  - **Category**: Concurrency Safety
  - **Suggested fix**: Rebase only the expected dependency-induced delta, such as the newly created managed format appearing at score zero, reject any other semantic difference, and add a regression where unrelated profile drift appears during format read-back and prevents the profile write with `LIDARR_PRESET_STALE`.

### MEDIUM

- **[F002]** `packages/rfmedia-cli/src/lib/config.ts:1449` — The 1 MiB expanded-data budget counts object entries rather than their UTF-8 key bytes. A configured pack can therefore exceed the documented bounded expansion using a very long accepted field key while remaining under the entry-count budget.
  - **Status**: Fixed
  - **Category**: Resource Bounds
  - **Suggested fix**: Include UTF-8 object-key bytes and conservative structural overhead in expanded-byte accounting, and add a regression test that rejects a configured pack containing an oversized object key.

- **[F005]** `packages/rfmedia-cli/src/actions/lidarr/profile-presets.ts:173` — `executionMetadata()` always reports `lane: "local-only"`, so writes scheduled in the destructive lane are falsely described in machine results.
  - **Status**: Fixed
  - **Category**: Result Contract
  - **Suggested fix**: Project the scheduler metadata's actual lane and assert destructive execution metadata in an action regression test.

- **[F006]** `packages/rfmedia-cli/src/commands/lidarr-presets.ts:118` — The fixed CSV schema omits safe recovery details from error-bearing outcomes, including code, phase, resource path, retryability, and next action.
  - **Status**: Fixed
  - **Category**: Output Contract
  - **Suggested fix**: Add fixed error columns, populate them for failed and uncertain outcomes, and add a failed or uncertain CSV regression test.

- **[F007]** `packages/rfmedia-cli/src/lib/lidarr/profile-presets.test.ts:113` — The built-in digest assertion compares the digest array to itself, so it cannot detect policy drift or a documentation mismatch.
  - **Status**: Fixed
  - **Category**: Test Completeness
  - **Suggested fix**: Assert the three documented literal built-in digests.
