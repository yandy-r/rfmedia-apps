## Summary

The third independent review confirmed the projection, targeted-row, signal-rendering, and output
ordering fixes, but reproduced a critical post-open SQLite WAL redirection race. It also found
three high-severity server-uniqueness, cancellation, and shared signal exit-code gaps plus two
medium acquisition-bound and source-of-truth documentation inconsistencies. A third fix cycle and
fresh approval review are required before opening the pull request.

## Findings

### CRITICAL

- **[T001]** `packages/rfmedia-cli/src/lib/db.ts:396` — SQLite canonicalizes the descriptor alias back to the mutable original path and closes the caller's descriptor before updates; a WAL-mode post-open path swap can redirect a guarded update into a crafted replacement database.
  - **Status**: Fixed
  - **Category**: Security
  - **Suggested fix**: Do not treat the descriptor alias alone as a safe writable binding. Pin the main database and journal/WAL/SHM namespace through commit with a transaction/VFS boundary, or require and verify a trusted non-renamable parent for the full apply. Add a deterministic WAL test that swaps after open and before update and proves no replacement changes.

### HIGH

- **[T002]** `packages/rfmedia-cli/src/actions/reconcile.ts:737` — The bounded guard refetches only reviewed track IDs, so it cannot detect a newly introduced second track at the same path or a new track where the reviewed path previously had none.
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Add an uncached, library-scoped exact-path lookup returning up to two matches, or an equivalent versioned uniqueness precondition, and compare the complete current match set immediately before mutation; add same-path duplicate zero-write coverage.

- **[T003]** `packages/rfmedia-cli/src/actions/reconcile.ts:950` — Cancellation during exact-track freshness is caught as stale evidence, and an aborted post-acquisition can add verification failure, producing exit 1 instead of structured cancelled/130.
  - **Status**: Fixed
  - **Category**: Completeness
  - **Suggested fix**: Preserve cancellation in the pre-write and post-acquisition catches, retain completed outcomes, mark unstarted work cancelled, and add an in-flight final-path exact-track cancellation regression.

- **[T004]** `packages/rfmedia-cli/src/lib/signal-handler.ts:177` — The shared manager selects 130/143 but existing signal-aware commands can overwrite it while unwinding because signal exit-code ownership is only preserved locally by reconcile.
  - **Status**: Fixed
  - **Category**: Correctness
  - **Suggested fix**: Make the signal-selected code authoritative at the shared lifecycle boundary or centralize command exit-code assignment; add compatibility coverage for an existing signal-aware command unwinding after interruption.

### MEDIUM

- **[T005]** `packages/rfmedia-cli/src/actions/reconcile.ts:237` — Discovery and scheduling materialize every candidate path and one promise per item before bounded workers run, with no file-candidate cap or streaming admission boundary.
  - **Status**: Fixed
  - **Category**: Performance
  - **Suggested fix**: Enforce a documented hard reconciliation file-candidate limit before scheduling metadata reads, or stream discovery through a bounded queue; add a limit-plus-one regression proving no parsing is scheduled past the boundary.

- **[T006]** `docs/plans/125-metadata-drift-reconciliation/feature-spec.md:366` — Approved design/analysis artifacts still define metadata parse failure as a per-file successful result, contradicting the implemented acquisition-error/no-result contract.
  - **Status**: Fixed
  - **Category**: Completeness
  - **Suggested fix**: Update the settled feature spec and design contract to define nonzero acquisition failure and error-envelope output without a reconciliation result, and mark the superseded analysis note accordingly.

None.
