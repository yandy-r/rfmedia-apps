# Cloudflare Tunnel

## Overview

This project runs `cloudflared` as a remotely managed Cloudflare Tunnel connector. Terraform in
`infra/terraform/cloudflare/` creates tunnel `rfmedia-apps-tf`, its remote ingress configuration,
and proxied CNAME records. Terraform state remains local to that directory (`terraform.tfstate`),
is gitignored, and contains the tunnel secret. Treat it as a secret. A remote backend such as R2 is
a future upgrade.

Tunnel hostnames live in `infra/terraform/cloudflare/terraform.tfvars`:

```hcl
ingress = {
  "tokenhop"  = { domain = "primary" }
  "plex-sync" = { domain = "media" }
}
```

These entries publish `tokenhop.${DOMAIN}` and `plex-sync.${DOMAIN2}`. Terraform derives each zone
from the hostname's final two DNS labels and creates a proxied CNAME to
`<tunnel_id>.cfargotunnel.com`.

## Architecture

```text
External client
  -> https://tokenhop.${DOMAIN} or https://plex-sync.${DOMAIN2}
  -> Cloudflare edge (proxied CNAME)
  -> cloudflared container (remote tunnel configuration)
  -> https://traefik:443 (SNI: requested hostname; HTTP/2 origin)
  -> Traefik router and Authentik policy, where configured
  -> application container on apps network
```

Every tunnel hostname targets `https://traefik:443`. `origin_server_name` is its hostname and
`http2_origin` is enabled. Never point tunnel ingress at an application container directly.
Traefik remains owner of TLS, routing, and Authentik middleware.

Internal and tailnet clients continue using Tailscale split-DNS and Docktail-advertised services.
Public DNS CNAME records affect clients not using that split-DNS configuration.

`PLEX_ADVERTISE_URL` already advertises `https://plex.${DOMAIN2}:443`, so Plex needs no
reconfiguration after tunnel cutover.

### Why route through Traefik

- Reuses existing routers, TLS certificates, and Authentik policy in `compose.yml`.
- Keeps tunnel origin behavior consistent for every public hostname.
- Plex intentionally has **no** Authentik middleware, required for third-party Plex token auth.

## One-time Cloudflare setup and cutover

### 1. Add required credentials

Create a Cloudflare custom API token with these permissions:

- **Account** → **Cloudflare Tunnel** → **Edit**
- **Zone** → **DNS** → **Edit**
- **Zone** → **Zone** → **Read**

Limit zone resources to zones for `${DOMAIN}` and `${DOMAIN2}`. Add account ID and token to your
secrets store:

```bash
# dotenvx (encrypted .env.local)
dotenvx set CF_ACCOUNT_ID <account-id> -f .env.local
dotenvx set CF_TERRAFORM_API_TOKEN <api-token> -f .env.local

# 1Password (.env.local holds op:// references): set the fields on the referenced item
op item edit RFMEDIA_SECRETS --vault EnvSecrets \
  '\.env\.local.CF_ACCOUNT_ID[concealed]=<account-id>' \
  '\.env\.local.CF_TERRAFORM_API_TOKEN[concealed]=<api-token>'
```

With 1Password, also add a `CF_TUNNEL_TOKEN` field (any placeholder value) and its `op://`
reference in `.env.local` so the wrapper has a field to write the generated token into.

`CF_TUNNEL_TOKEN` is generated by Terraform. Do not hand-enter it.

### 2. Resolve explicit DNS records

Before Terraform creates records, delete existing explicit DNS records for `tokenhop.${DOMAIN}` or
`plex-sync.${DOMAIN2}` in Cloudflare Dashboard, or import them into Terraform. A wildcard record
is fine; an explicit CNAME overrides it.

### 3. Create remote tunnel and DNS records

```bash
npm run tf:plan:apply cloudflare
```

This initializes Terraform and runs interactive `terraform apply`. Wrapper `scripts/tf.sh` loads
`.env.local`, maps `DOMAIN`, `DOMAIN2`, and `CF_ACCOUNT_ID` to Terraform variables, and passes
`CF_TERRAFORM_API_TOKEN` as `CLOUDFLARE_API_TOKEN`. Set `TF_ENV_FILE` to use another environment
file.

The wrapper picks the secrets tool from the file: a dotenvx-encrypted file (it has a
`DOTENV_PUBLIC_KEY` header) loads with `dotenvx run`; anything else loads with
`op run --no-masking`, resolving `op://` references. Set `TF_ENV_TOOL=dotenvx` or `TF_ENV_TOOL=op`
to force one.

After successful apply, wrapper writes `tunnel_token` as `CF_TUNNEL_TOKEN`: with dotenvx, encrypted
into the env file via `dotenvx set`; with 1Password, into the item field that the
`CF_TUNNEL_TOKEN` reference points at. Terraform commands are also available as:

```bash
npm run tf:plan:cloudflare
npm run tf:apply:cloudflare
npm run tf:plan:apply:cloudflare
```

`tf:plan` initializes and saves `tfplan`; `tf:apply` applies saved `tfplan`; `tf:plan:apply` shows
an interactive plan and asks for confirmation. Omit stack name to run every stack under
`infra/terraform/`.

### 4. Deploy connector

```bash
rfapps deploy -s cloudflared --use-dotenvx .env.local --yes  # dotenvx
rfapps deploy -s cloudflared --use-op .env.local --yes       # 1Password
```

Connector runs `tunnel --no-autoupdate --metrics 0.0.0.0:2000 run` with `TUNNEL_TOKEN`. It uses no
local config file or credentials volume. Healthy logs show registered tunnel connections; metrics
remain available on port 2000.

### 5. Verify public route

```bash
curl -sS https://tokenhop.${DOMAIN}/api/health
```

Run from a client that resolves public DNS, not Tailscale split-DNS.

### 6. Retire old locally managed tunnel

After verification, delete old CLI-created tunnel and credentials:

```bash
cloudflared tunnel delete rfmedia-apps
rm "${DOCKER_DIR}/cloudflared/credentials.json"
```

Remove `CF_TUNNEL_ID` from environment files. Old `cloudflared tunnel login`, `tunnel create`, and
`tunnel route dns` commands are no longer part of this deployment.

## Exposing additional services

1. Add hostname entry to `infra/terraform/cloudflare/terraform.tfvars`:

   ```hcl
   ingress = {
     "myservice" = { domain = "media" }
   }
   ```

   `primary` expands to `${DOMAIN}`. `media` expands to `${DOMAIN2}`.

2. Ensure `compose.yml` has Traefik router for resulting `Host`. Apply suitable Authentik middleware
   unless service requires direct token authentication like Plex.

3. Apply tunnel and DNS configuration:

   ```bash
   npm run tf:plan:apply cloudflare
   ```

No container restart needed. Cloudflare pushes remote configuration to connector.

## Security and operational notes

### Terraform state and tokens

- `infra/terraform/cloudflare/terraform.tfstate` contains tunnel secret. Keep it local, gitignored,
  and protected like `.env.local`.
- `CF_TERRAFORM_API_TOKEN` and generated `CF_TUNNEL_TOKEN` are secrets. Store them with dotenvx or
  1Password.
- `CF_TUNNEL_TOKEN` is Terraform output. Regenerate through Terraform; never manually set it.

### tokenhop exposure

`tokenhop.${DOMAIN}` is public. The dashboard is guarded by native tokenhop login, and `/v1`
(OpenAI-compatible API) by native tokenhop API keys; neither router uses Authentik. Require API keys
and review access.

### Plex exposure

- Plex is protected by Plex authentication only; Authentik is omitted by design for Trakt and
  similar integrations.
- Anyone reaching `https://plex.${DOMAIN2}` can attempt Plex login flows. Use strong Plex account
  passwords and review authorized devices periodically.

### Streaming over tunnel

Because `PLEX_ADVERTISE_URL` may include a public hostname, remote Plex clients away from tailnet
may stream through Cloudflare rather than Tailscale. That can affect performance and conflict with
Cloudflare terms for heavy media traffic.

Recommended mitigations:

1. **Advertise URL ordering** — list Tailscale URL first, then sync hostname:

   ```bash
   PLEX_ADVERTISE_URL=https://plex.<TS_DOMAIN>:443,https://plex-sync.<DOMAIN2>:443
   ```

2. **Cloudflare WAF** — block streaming paths on tunnel hostnames while allowing sync/API traffic.
3. **Dedicated sync hostname** — keep only `plex-sync.${DOMAIN2}` in tunnel ingress.

#### WAF rule (API)

DNS-only API tokens (`CF_DNS_API_TOKEN`, `CF_MEDIA_API_TOKEN`) cannot manage WAF rules. Create
separate token:

1. Open [Cloudflare API Tokens](https://dash.cloudflare.com/profile/api-tokens) → **Create Token** →
   **Create Custom Token**.
2. Permissions:
   - **Zone** → **Firewall Services** → **Edit**
   - **Zone** → **Zone** → **Read**
3. Zone Resources: **Include** → **Specific zone** → zone containing `${DOMAIN2}` (for example
   `rfmedia.media` when `DOMAIN2=home.rfmedia.media`).
4. Create token and add it to `.env.local`:

   ```bash
   CF_WAF_API_TOKEN="your-waf-token"
   ```

5. Apply rule (idempotent):

   ```bash
   # dotenvx
   dotenvx run -q -f .env.local -- python3 scripts/cloudflare/apply-plex-streaming-block.py

   # 1Password
   op run --env-file .env.local -- python3 scripts/cloudflare/apply-plex-streaming-block.py
   ```

Script blocks `/video/:/transcode*` and `/library/parts/` on `plex.${DOMAIN2}` and
`plex-sync.${DOMAIN2}` while leaving metadata, session, and timeline endpoints available for Trakt
and similar sync tools.
